# M1-06 库存Agent运行与接口

本阶段接入真实任务、查询、草稿与回执服务；DeepSeek负责提取受限计划，不能确认或直接改库存。2026-11-04已配置本机密钥并完成12次真实DeepSeek调用的小样本联调，流程、耗时与已知token有实际证据；扩大样本质量和精确费用尚未核定，见[真实联调记录](../design/qa/m1-06/live-validation.md)。售后真实服务和维修能力仍待M2/M3。

## 启动和配置

沿用[后端开发说明](backend-development.md)创建隔离数据库、安装requirements.lock及执行Alembic升级。迁移0007新增任务、子项及LangGraph PostgreSQL检查点表。已有任务或检查点时拒绝降级；升级现有审核/业务库前先备份。本轮仅升级专用测试库和新建M1-06样例库，原审核库仍为0006。

继续兼容服务端环境变量`DEEPSEEK_API_KEY`；可选`DEEPSEEK_MODEL`，默认`deepseek-flash`。环境变量由服务进程启动时载入，页面保存按下述规则立即生效。密钥不进入聊天、启动日志或Git。配置状态只表示存在密钥，不证明鉴权、额度或模型可用；未配置时任务会保存并显示原因，库存查询和人工表单独立可用。

2026-11-04审核修订：负责人可在[DeepSeek设置](http://127.0.0.1:8002/#deepseek-settings)自行输入、更换或清除密钥，不再要求通过系统环境变量设置。页面密码框初始为空，勾选确认后保存；保存不会调用付费模型。默认保存在运行服务的本机.local/deepseek-settings.json，Windows以当前服务用户DPAPI保护，其他系统使用权限受限文件。可在服务配置JSON设置deepseek_settings_file固定文件位置；跨工作目录部署应使用绝对路径。文件不入数据库/Git/浏览器持久存储，API不回显密钥。原环境变量继续兼容，本机配置优先；清除会写停用标记防止回退旧环境密钥，重新保存后启用。部署更换服务用户/机器时应重新配置，不能把密文复制当作完整迁移。

接口固定为`https://api.deepseek.com/chat/completions`，JSON模式、关闭思考和流式输出，输出上限2048 token，30秒网络超时。2026-11-03核对依据：[官方接口说明](https://api-docs.deepseek.com/)、[JSON模式](https://api-docs.deepseek.com/guides/json_mode/)、[请求参数](https://api-docs.deepseek.com/api/create-chat-completion/)。当前已完成首轮真实调用，不自动切换为规则解析或演示。

## 已实现边界

- 查询：库房必填的库存总览，型号可省略表示全部型号；预留、有效进货统计、单库房型号流水。数量、覆盖范围、T0及截至时间来自现有服务。
- 草稿：建账、入库、普通出库、留货、提货、取消、盘点、原单数量更正；正式确认仍走既有操作接口。
- 入库的到货依据/备注、普通出库的办理依据/备注均可选，Agent与人工表单采用相同后端校验；留货/提货/取消/更正等其他业务依据及T0边界核实条件保留。
- 建账只有明确“期初预留为0”才生成无期初预留的Agent草稿；未知数量先补问，非零预留引导原表单逐笔填写。模型不把未解析的客户留货默认为0。
- 唯一标准名称/已登记别名可匹配；库房额外统一全角数字、中文编号及库/库房/仓库的等价后缀，如2号库与二号库房。保留名称前缀，不把12号库当2号库；等价重名、模糊或未知对象先人工选择。该规则仅用于Agent，不改变库房名称、ID或人工表单。
- 模型计划按动作清除无关字段。数量、实物、期初预留、更正目标量及留货依据标签必须给出原文连续引文（内部`evidence`），后端核对数值/肯定依据；不从型号/日期猜数量，含糊“两三台”“一百二”留空。依据文本必须来自原文并填写basis_note，reference仅用于原单/预留编号。引文校验不是通用语义证明，确认前仍须核对完整原文。
- 补充时模型返回完整未完成项；未核实数值清空，不合并回旧数量。提货/取消须选具体预留，换客户、库房或型号会清除旧预留选择。
- 补充说明立即撤销未提交旧预览，即使模型失败或超限也不能继续确认旧版；原表单仍可重新填写、预览。已成功事项保留，修改成功事实须另行更正。
- 一个任务至多4项，当前创建人独立访问。任务列表显示最近30项；流水卡片展示前50条，完整范围可从流水页查询。未实现语音、照片识别或后台队列。

## 接口契约

所有接口要求登录，任务接口要求当前`inventory.read`；每个工具和正式操作另核其业务权限。写请求沿用同源Origin与CSRF。UUID由服务器关联；没有客户端可指定的检查点线程或确认授权字段。

| 接口 | 请求 / 返回 |
| --- | --- |
| `GET /api/agent/status` | `provider,model,configured,test_double`；不返回密钥。测试注入明确标识，生产默认不注入 |
| `POST /api/agent/tasks` | `{request_id:UUID,text}`；201返回任务，同人同标识同文本复用，同标识换文本409 |
| `GET /api/agent/tasks` | 默认当前用户最近30项；month=YYYY-MM返回北京时间创建日期落在整月的全部本人任务，pending_only=true返回本人未完成任务且不限最近30项。各项从真实操作结果核验，非法月份422 |
| `GET /api/agent/settings` | 仅account.manage；返回configured/readable/source/model，不返回密钥。source为local/environment/disabled/unreadable |
| `POST /api/agent/settings` | 仅account.manage及Origin/CSRF；{api_key,confirmed:true}。密钥8～512位无空白ASCII，原子保存本机，下次调用立即读取；不调用模型 |
| `DELETE /api/agent/settings` | 仅account.manage及Origin/CSRF；写停用标记，后续不回退环境密钥；任务和库存保留 |
| `GET /api/agent/tasks/{id}` | 本人的任务及当前有权子项，非本人404 |
| `POST .../{id}/run` | `{expected_version,reply?}`；领取、解析和受限执行；不执行确认 |
| `POST .../{id}/select` | `{expected_version,item_id,field,value}`；field仅warehouse/model/customer/reference，value必须属于当前候选 |
| `POST .../{id}/refresh` | `{expected_version}`；按原操作读取最新状态/回执 |
| `POST .../{id}/cancel` | `{expected_version}`；停止未提交部分，不撤销已成功事实 |

任务返回`id,text,followups,version,state,question,can_retry,items,created_at,updated_at,budget`；子项返回`id,action,state,question,candidates,draft,result`。`draft`复用既有草稿契约；写入成功的`result`来自`Operation.result`，查询result为原查询结构。前端类型见[contracts.ts](../../app/web/contracts.ts)，严格请求见[schemas.py](../../app/agent/schemas.py)。版本/领取冲突409，非法字段/候选422，当前无权限403；外部模型错误清理领取并返回任务失败提示，不回显原始异常。

## 持久化、预算和恢复

模型调用前用短事务领取120秒租约，保存任务版本及栅栏；网络期间不持有业务事务。检查点线程为服务器任务ID加输入修订号。LangGraph只持久化解析节点，业务事实仍由任务子项关联草稿、操作及回执；不假定检查点与业务同时提交。详情、刷新及重启后先读原操作，已成功不会重新建账。原计划已完成解析但应用事务丢失时重用检查点，领取过期后可继续；旧工作者不能越过栅栏落地。

开发上限为每任务6次整理尝试、12次工具调用、已知总token达到12000后停止新调用；请求JSON限64000字节、响应262144字节。失败尝试也计数；token只能统计返回且通过校验的usage，失败或断连可能发生未知消耗。12000是启动下一次调用的截止线，单次返回可能超过该值，不是精确人民币限额。2026-11-12按用户反馈将每任务整理上限由3次提高到6次，首次整理、补充及重试共用额度。金额预算部署前确定；不将待定金额当本阶段代码未完成，也不宣称已实现每日人民币限额。没有无限自动重试，失败保留已有结果并提供原表单。

PostgresSaver检查点表按锁定的`langgraph-checkpoint-postgres 3.2.0`冻结在Alembic中，不在启动时调用setup隐式DDL；升级该依赖必须核对上游迁移。LangSmith追踪在本流程关闭，不向遥测平台发送任务材料。[官方持久化文档](https://docs.langchain.com/oss/python/langgraph/add-memory)是框架行为依据。

## 对话补问、删除和计数

Agent 按动作列出能确定的缺项。「准备出库」先询问普通出库或预留提货。对象缺失时请用户用文字补充。同名、模糊匹配及按已知对象筛出的预留单保留候选，可手选或继续用文字说明。数量、时间和留货依据类型等缺项通过对话补充。后端预览发现的 T0 边界也显示在对话。非零期初留货需要按客户和剩余量逐笔核对。

待核对可删除本人未提交的草稿，库存任务可在工作台、待核对及任务详情删除。删除调用带当前版本并经过 Origin 和 CSRF 校验。后端保留记录并将尚未确认的操作标为失效。已登记的库存、流水及原回执继续按既有权限读取。月历只按创建日期计入已完成任务，选中日期仍可查看当天的未删除任务。任务的各项草稿都已删除时，任务退出月历；有已登记事项或其他待办的任务仍可查看。

接口为 `DELETE /api/drafts/{id}?expected_version=n` 和 `DELETE /api/agent/tasks/{id}?expected_version=n`。首次和重复删除均返回 204。浏览器实测见[核对记录](../design/qa/agent-conversation/README.md)。
