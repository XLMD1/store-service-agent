## 实际行为

- “客户预留”入口及页面标题统一为“预留查询”；新增留货入口用“办理留货”区分动作。客户表单统一在“客户资料”，库房与型号页只保留一个跳转按钮。
- 库房登记/修改只有一个名称输入，内部唯一编号后端生成，旧code与ID保留；同名库房在候选、下拉及维护摘要只读显示区分编号，不新增输入框。
- 查询先输入库房名，型号默认为全部；精确唯一名称直接查询，模糊或同名需人工选候选。输入内容变化清除旧结果，不能把旧库房数量冒充新条件。
- 一个库房多个型号沿用既有独立账户，后端计算分项及已建账型号合计，不跨库。未建账型号保留null，单独列“库存未知”，不参与合计；所有型号都未建账时合计未知。
- 页面先查询、再日常办理，基础设置折叠；分项可查看本对象预留/流水或为未建账对象预填建账表单。切换页面回到顶部，同账号返回库存页恢复已查询对象。
