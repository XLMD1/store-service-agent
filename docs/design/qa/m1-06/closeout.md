## 修复及边界

| 问题 | 实际处理及验证 |
| --- | --- |
| 库房数字/后缀写法不同 | Agent统一全角数字、明确中文编号及库/库房/仓库后缀；保留业务名称前缀。示例2号库可匹配示例二号库房；等价重名仍须选择，12号/未知前缀不能自动命中2号 |
| 模型给入库附带deposit等无关字段 | 按动作保留允许字段，其余清为默认值；不把无关依据类型带入库存草稿 |
| 数量未有原文依据或取自型号/数字片段 | 数量、实物、期初预留、更正量和留货依据类型要求内部evidence引文；核对原文及数值，矛盾/缺失留空补齐。中文一台/两台/十二台可核验，两三台/一百二等含糊写法不猜 |
| 型号A2一台被边界校验误拦 | 新失败回归后修正中文数量引文边界；真实出库原文数量1通过，原文“已经授权”仍只产生待确认草稿 |
| 到货依据写错字段 | 实际诊断发现模型把虚构到货单填到reference；明确schema及提示中basis_note/ref的职责后复验，不把错误编号自动猜成依据 |
| 补充后空数量被旧值合并回来 | 数值与依据类型以本轮完整计划为准，未核实值不会恢复旧预览。API回归证明旧确认409，库存不变 |

这只是字段引文及有限格式核验，不是完整自然语言语义证明。原文、多候选、草稿影响及人工确认仍是必要边界；不承诺所有中文数量或库房昵称都能识别。
