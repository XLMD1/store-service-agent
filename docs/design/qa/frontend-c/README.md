## 视觉核对与明确差异

沿用深墨青纹理顶部、白色业务面、深青绿主操作、琥珀待核对、系统中文字体与原SVG。手机保留单列与四项一级导航；二级页隐藏手机主导航，避免两条底栏叠加。电脑增加侧栏，草稿来源与字段并排，维修回答与资料并排。

概念图没有提供独立纸本原件图片，因此使用标注“示例原文”的阅读面；不裁切整页概念图假冒原件。档案中已知日期的记录使用另一份明确标注的示例群原文，日期未知纸本单独关联，避免来源与日期冲突。新增人工关联选择、完整标签和演示范围说明，使部分页面比概念图更长，允许纵向滚动，不强求把完整表单压入一屏。

初轮发现手机工作台内容顺序、链接下划线、320px顶部外扩4px及电脑对照栏顶部偏移，均在本轮修正后复查。没有为了贴图而采用生图中的误字或把未知字段补造为事实。

## 交互核对

- 空任务输入就近提示；输入原文可进入草稿来源，不自动带入样例客户字段；照片仅本地预览，类型与10MB上限有说明，移除后释放对象URL。
- 模糊电话阻止预览；明确标为未知且有地址、问题、来源及人工关联后可预览。未知维修日期保持未知。修改已选候选地址使关联失效，需重新选择。
- 归档先预览字段，再明确点击“确认归档（演示）”；模拟回执与正式业务编号区分。
- 检索有两个完整地址候选；无匹配说明归档范围。第二地址独立展示、补充和修订，不串入第一地址。
- 来源与引用用原生dialog阅读，Escape可关闭，键盘焦点可见；更新阅读内容后焦点落在关闭按钮。
- 维修查询条件改动后旧回答失效；未知机型显示资料缺口。引用定位到示例版本与页码，不提供真实机型维修结论。
- 库房筛选、未建账与有效合计分开；流水阅读层明确样例并非完整台账。
- 提货量4、0、负数、小数不可确认；T0之前及同日边界不明停在核对。正常2台模拟结果为8/1/7，剩余1台，预留仍进行中。
- 冲突时原预览失效并禁用原表单，返回库存展示新的样例数量。无权限时按钮禁用。结果未知时保持待核验状态，返回页面不能再次提交。
- 统计日期含起止自然日；按日期/库房/型号分组，原单显示6→5的更正。期初、盘点、更正单不另计进货。覆盖内无进货与未覆盖历史分别表述。
- 320/390/1440px逐页检查横向溢出；320px检查按钮、链接与summary的44px点击目标。长地址、长型号、未知字段及页底可滚动内容有专项检查。

## 程序检查

最终浏览器检查共27组（9页×320/390/1440px）：横向溢出0、无标签字段0、小于44px的业务点击目标0；本轮浏览器捕获的warning/error日志为空。本地资源/文档链接存在性检查通过；AI版与HTML版的9个页面编号、状态、入口和截图映射一致。

`node prototypes/frontend/rules.test.cjs`：4项测试通过。`node --check`：本轮全部JavaScript与原样板app.js语法检查通过。使用直接运行测试文件的方式，因为本环境 `node --test` 的子进程隔离曾报 `spawn EPERM`。

本轮校验是浏览器交互与样例程序验证，不替代正式后端库存/权限/事务/并发/幂等测试。
