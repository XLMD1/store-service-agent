## 目标与架构

基线e61dc59，分支codex/m1-06。在现有FastAPI/SQLAlchemy/PostgreSQL上接入单Agent：自然语言→受限JSON计划→查询或库存草稿→登录人员点击现有确认按钮→原操作回执核验。模型不取得确认能力，不直接写库存表。LangGraph管理解析流程，持久化检查点独立于业务事实；任务、子项和草稿/操作关联以业务库为准，恢复先查原结果。

用户选择DeepSeek。按2026-11-03官方接口使用https://api.deepseek.com/chat/completions，默认deepseek-flash，服务端可配置模型。密钥只通过DEEPSEEK_API_KEY提供，不进入前端、日志、仓库或聊天。未配置或API失败时保留任务、提供重试/原表单，不能拿规则解析或演示冒充真实模型。

技术：沿用Python3.12/FastAPI/PostgreSQL、经典JS与C设计；引入实际需要的LangGraph及PostgreSQL检查点依赖。新增库表通过Alembic，模型请求期间不持有业务事务。请求内受控执行、可过期领取与栅栏令牌防重入；不提前引入消息队列或独立平台。

## 约束与范围

- 仅库存：库存/预留/流水/有效进货查询；既有建账、入/出库、留货/提货/取消、更正/盘点草稿。售后和维修真实服务仍属M2/M3。
- 每个任务只允许当前创建者访问，恢复重核账号/权限、草稿版本及原操作；客户端不能用任意线程ID跨任务访问。
- 多笔请求拆分子项，分别确认及呈现成功/未完成；取消不撤销已成功事实，未提交子项不能随后以旧确认执行。
- 唯一名称或已核实别名可匹配；未知/多候选必须人工补选；不接受模型编造UUID、授权标志、SQL或工具名称。
- 每任务有限模型轮次、工具次数、输出token、超时；初始上限为开发默认，记录实际调用/token，不虚构人民币费用；正式预算待D-06核定。
- 测试只使用显式store_agent_m1_test隔离PostgreSQL，不清空审核库；迁移审核环境前先备份并保留旧数据。本轮不接收真实客户资料，不把测试替身当实际DeepSeek调用成绩。

## 设计与接口

新增app/agent/models.py保存AgentTask（文本、主体、版本、状态、预算计数、领取与期限）与AgentTaskItem（序号、已校验参数、候选/缺项、草稿及操作关联、结果）。状态：processing / missing / awaiting_confirmation / awaiting_verification / completed / failed / cancelled。正式结果始终从Operation.result读取。

app/agent/schemas.py约束请求/模型JSON；provider.py只调用DeepSeek解析任务，返回受限动作和名称/日期/数量，不执行工具；tools.py将真实名称/别名/预留候选解析为内部对象并调用现有业务服务；service.py负责领取、持久化、版本、防重、恢复和取消；router.py提供/api/agent/tasks创建/列表/详情、run/补充/refresh/cancel以及模型可用状态。所有写入口沿用Origin/CSRF。

工作台#home：文字任务→保存任务并运行、真实任务状态与继续入口。#task?id=显示用户原文、候选/缺项、逐笔查询或草稿影响、继续现有表单/人工确认、刷新核验、取消未提交和重试；#pending纳入当前有权任务。模型不可用就近说明且保留库存表单入口。独立mock入口继续明确标识，不混用演示与真实任务。沿用既有C电脑侧栏、手机一级四导航、二级返回及统一picker；设计资源两版和截图同步。
