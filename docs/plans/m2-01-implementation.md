# M2-01 来源保存与受控阅读

本阶段按[开发计划](development-plan-v1.0.md#7-m2售后档案闭环)先交付手工原文。以虚构材料验证，照片规格与正式保留规则按 D-04 核定。

1. 在专用 PostgreSQL 库验证登录、CSRF、原文无损保存、同一请求重试、未归档隔离、撤权及重启恢复。先写接口测试，再加入 `app/sources/` 与 Alembic 迁移。
2. 原文和提交元信息随同一个数据库事务保存。读取每次重新校验 `service.read` 及提交者，提交校验 `service.draft`。同提交者、同请求标识、同内容返回原结果，内容变化返回冲突。
3. 沿用 C 方向接入上传和阅读。验证成功状态来自后端，失败保留输入，刷新可回到保存结果。同步页面编号、截图与验证记录。
4. 依据 D-04 完成照片限制与保存方式核对，再验证原图、识别失败后保留以及跨记录访问边界。关联授权随草稿和档案阶段落地。

## 2026-11-11 照片保存与页面验证

- 开发配置支持 `source_files_dir` 和 `source_photo_max_bytes`。默认存放于忽略目录 `.local/service-sources`，每次一张 JPEG 或 PNG，上限 5 MiB、2400 万像素。原文沿用每份 12000 字符默认上限。页面从接口取得限制。正式留存期限、删除规则和真实样例仍按 D-04 核定，开发目录由管理员核对清理。
- `POST /api/sources/photos` 接收单张照片的 Base64 JSON 与可选来源信息。上传经权限、CSRF、字节、格式与尺寸校验。写入暂存文件、落盘、原子移动并按摘要验证可读取后，来源事务才提交。发生提交结果不明时按同一请求标识重试。进程异常留下的孤立文件应在维护窗口核对数据库引用后清理。
- `GET /api/sources/{id}/original` 每次校验当前售后权限和提交者。源文件独立保留，读取校验原始大小和摘要；文件暂缺返回 503，原编号及元信息保留。同编号链接不授予其他用户访问权。草稿授权、识别状态和多记录关联在 M2-02/03 接入。
- 使用 Alembic `0009_source_photos` 保留已有文字行。存在照片来源时迁移拒绝降级。运行环境升级需将数据库与原件目录纳入同一备份点。
- 完整后端 265 项、前端 68 项、lint、类型检查、静态 mock 构建及双视口端到端检查通过。详见[页面核对](../design/qa/m2-01/README.md)。本轮数据为虚构样例，用户于 2026-11-11 确认 M2-01 审核完毕。
