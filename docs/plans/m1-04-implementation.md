# M1-04 普通出库、留货与提货实施记录

依据：PRD FR-08～FR-10及库存不变量、架构第8节、阶段计划M1-04。用户已授权本阶段；完成后等待审核，不自动实施M1-05，不提交/推送/部署。

## 范围与技术口径

- 扩展统一草稿/操作流程，支持普通出库、留货、取消、预留提货；沿用当前权限、T0、版本、启用状态校验和响应未知后的原操作核验。
- 普通出库只扣可售；留货仅加R；取消仅减R；提货同时减H/R。具体预留的已提/已取消/剩余和状态保持一致，不跨客户借用数量，不自动到期释放。
- 预留操作只接受reservation_id，不接受改写库房或型号；确认按操作→草稿→账户→预留顺序锁定，相关版本绑定，余额/预留/原单/流水/回执同事务成功或回滚。
- 新留货登记口头/定金/全款标签，不核算或推断实际收款；旧期初预留标签未知保持空。原单关联具体预留，支持后续更正追溯，不在本阶段做更正。
- 接单职责可人工登记客户引用并留货/取消，进出货职责可出库/提货；未知联系字段仍沿用M0样例口径，显式选定可区分的客户，不创建售后档案、不按手机号自动合并。
- 增加预留检索、明细和流水阅读；库存查询只显示后端事实。沿用C方向和同源页面，审核库独立于测试库，保留既有审核数据。

## 任务与完成条件

1. 失败测试先行：数量与预留关联、部分提货/取消、超额及非法量、角色/撤权/CSRF、旧版/重复/参数冲突、同草稿不同操作、并发最后库存、正式事务回滚及恢复。
2. 最小迁移与业务服务；真实PostgreSQL完整回归、迁移往返/保留旧数据通过。
3. 出库、留货、提货/取消及预留/流水页面接真实API；手机/电脑核对，截图和设计规范两版同步。
4. 独立审查、必要修复和最终验证，逐项登记实际覆盖的AC；M1整体、真机及生产仍分别表述。
