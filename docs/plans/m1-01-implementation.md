# M1-01 工程、身份与环境实施记录

**目标**：交付可复现的 FastAPI/PostgreSQL 服务基础、账号初始化与管理、独立会话、当前权限校验和 CSRF 防护。完成后等待用户审核，不进入 M1-02。

**依据**：[架构第17节](../architecture/store-service-agent-architecture-v1.0.md#17-m0细化m1首个切片契约)、[阶段计划](development-plan-v1.0.md#6-m1库存业务闭环)。本次用户已授权开始 M1，随后要求每个小阶段完成后审核。

## 实施选择与边界

- Python 3.12、FastAPI、同步 SQLAlchemy、psycopg 3、Alembic；依赖经实际安装验证后锁定。
- 服务端数据库保存账号、多职责与会话；仅存密码派生值、会话及 CSRF 令牌摘要。权限每次读取当前配置。
- 同源 Cookie 会话；所有写接口校验精确 Origin 与 CSRF，登录前通过只读接口取得临时 CSRF 凭据，登录后轮换。
- 首次负责人通过本机交互命令初始化；后续账号管理仅负责人可调用。管理请求要求显式确认，不提供默认密码。
- 本机专用 PostgreSQL 集群与两个独立数据库，仅监听回环地址；凭据和数据库目录放在忽略的 `.local/`，不接入已有数据库。
- 当前工作区包含必需的未提交 M0 基线，保留原地实施；不提交、推送或部署。界面在 M1-02 接入，本次不修改前端页面。

## 任务与验证

1. 环境与迁移：创建项目虚拟环境、依赖锁、配置、数据库连接和首批身份迁移。验证空库升级、降级、再升级；测试必须显式指定专用测试库。
2. 身份与权限（先失败测试，再实现）：匿名访问拒绝、正确/错误密码、多账号和多会话隔离、同账号退出不影响其他会话、服务重建后会话持续有效、多职责合并、停用/撤权即时生效。
3. 提交防护（先失败测试，再实现）：登录及管理/退出拒绝缺失或外站 Origin、缺失/错误 CSRF，令牌不跨会话通用；严格拒绝未知字段，账号管理显式确认，防止删除最后可用负责人。
4. 运行说明与验收：依赖校验、全部后端测试、既有前端测试与 diff 检查；记录实际结果及限制，等待审核。

## 尚不包含

库存余额、建账、草稿/操作、入库、Agent、安装包、真实账号与生产部署均不属于本次交付。38 项 AC 和 6 项 DEP 不因身份测试通过而标为业务验收通过。

## 执行证据

已完成环境、身份、提交防护及运行说明；实际验证记录见[阶段计划第13节](development-plan-v1.0.md#13-状态与阶段完成记录)。后续用户明确要求进入M1-02，作为本阶段获准继续的依据；M1-02另行实施并等待审核。

- 初始测试在缺少`app`时因功能缺失停止；实现后首轮22项身份测试通过。
- 独立审查提出登录无限尝试和多标签页CSRF问题：先补回归，3项分别复现403或未返回429；实现数据库限流和稳定会话CSRF后通过。并发限流、冷却恢复、成功重置账号预算和来源预算不重置均纳入测试。
- Origin补充回归覆盖账号创建、修改和退出；错误/缺失来源和CSRF均不写审计或账号。

- 本机默认uv缓存及pytest临时目录受限，改用项目缓存并避免共享临时目录；依赖下载和专用PostgreSQL启动经环境权限校验后完成。所有凭据仅在忽略的本地目录中。
