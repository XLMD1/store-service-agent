### 5.1 本轮样例口径与使用决定

2026-10-29用户明确选择“先用明确标注的示例推进”，并同意“样例先沿用PRD建议权限”。该决定适用于开发样例，不代替真实账号授权、人员职责或期初盘点确认。可以据此准备和实施M1开发切片；正式启用还需关闭相应真实数据缺口。

- 数据入口：[样例与验收数据说明](../../evals/README.md)。库房、型号、客户、日期和人员ID均为虚构，无真实客户电话、地址、密码或会话。
- 数量沿用PRD第8.4节；构造T0为`2026-10-01T00:00:00+08:00`，后续事件为10月2～7日。该时间仅用于测试，不能用作门店真实开账时间。
- 连续台账从未建账开始，依次得到`10/3/7 → 15/3/12 → 15/7/8 → 13/5/8 → 13/3/10 → 10/3/7 → 9/3/6`；期初进货为0，唯一入库5后有效进货始终为5。
- 期初客户甲预留3；新客户乙留货4、提货2、取消2后结束；期初预留仍剩3。没有为任何示例客户创建虚构售后档案。
- `independent_states`的未建账、10/3/7和已建账为0分别是独立前置状态；它们不能一起导入同一份账。原型中的独立余额仍只作历史界面样例。
- 样例权限是PRD产品建议的开发取值；角色可叠加，负责人没有自动的维修专业审核资格。具体权限代码为本轮技术约定，实际账户在M1由后端配置并执行校验。
