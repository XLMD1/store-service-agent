# M1-02 基础资料与建账实施记录

依据：架构第17节、PRD FR-07、阶段计划M1-02。用户已同意进入本阶段；完成后等待审核，不实施入库。

## 范围与实现选择

- 沿用FastAPI、SQLAlchemy和真实PostgreSQL，新增catalog、inventory、operations最小模块及迁移。
- 库房维护编号/名称/启用状态，型号维护名称/人工确认别名/启用状态；稳定ID、版本和审计保留。客户引用仅供期初预留，手工登记并选择，不建立售后档案。
- 负责人创建或修改建账草稿，缺项无可执行操作；后端计算预留/可售。修改后旧版操作失效，数据变化要求重新核对。
- 明确确认后同事务写账户、期初预留、原单、流水、操作回执；期初类型为opening，不计进货。库房/型号唯一键防止并发双建账。
- 成功请求按原操作标识返回原回执；同草稿不同操作标识也不得重复写入。操作只向原主体且当前仍有权限者开放；失败全部回滚。
- 原生HTML/CSS/JS同源页面，不引入构建框架；沿用C方向颜色/纹理/图标，生产代码放app/web。已有prototypes仅作历史样板。新增页面编号m1-login、m1-inventory、m1-opening、m1-catalog。
- 页面不预测成功，后端回执为准；只保留无敏感字段的草稿/操作编号供刷新恢复，断连后按原标识核验，不自动重新提交。

## 任务与完成检查

1. 写失败测试：基础资料权限/版本/停用、未建账与0、10/3/7和关联预留、无入库效果、重复及参数冲突、旧草稿、权限撤销、并发建账、事务失败回滚、应用重建与原回执恢复。
2. 实现迁移与API；真实PostgreSQL测试通过，迁移升级/回退/再升级且metadata一致。
3. 接入登录、库存查询、建账编辑/预览/确认/回执和资料维护；验证真实API全流程、窄屏/电脑、键盘焦点/长内容，记录截图。
4. 独立审查、完整回归，同步设计规范两版和阶段记录；只标记本切片已验证范围，不提前勾选整体AC/DEP。
