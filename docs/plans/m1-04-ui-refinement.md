# M1-04审核反馈：库房与库存页面优化

用户明确要求：客户预留改名预留查询；库房编号与名称合为一个输入；同库房多型号；仅输入库房名查全部型号；优化UI逻辑。沿用现有FastAPI/PostgreSQL和C方向；保留未提交M1-04改动，完成后用户审核，不推进M1-05或推送。

## 实现选择

库房界面仅填写名称，后端新建时生成内部唯一编号；原编号、稳定ID、历史修订保留，兼容旧API显式code。避免把名称直接当主键或批量改写旧账。多型号沿用既有warehouse_id/model_id唯一账户，无需新建从属表或更改台账。

查询输入库房名并给出现有候选；精确名称唯一时直接查，模糊或重名只列候选由人选，不能自动命中第一项。型号可选，留空查该库房全部已登记型号；已建账分项及合计由后端计算，未建账单独列未知，不推断实物或作零。

库存首屏以查询为主，日常办理独立分组，基础设置折叠；保留权限、人工确认、事务及幂等。统一预留查询、办理留货用词；基础资料只保留库房/型号，客户在独立入口登记，建账客户链接指向该入口。
