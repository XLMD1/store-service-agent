# 售后群聊整理对比

同一批 12 条人工标注的虚构群聊，覆盖明确档案号、带标签文字、口语新报修、回访补充、歧义和超范围请求。样例只含虚构地址代称和合成档案号。评估脚本只发送本目录固定样例。

在项目根目录运行：

```powershell
.venv\Scripts\python.exe -m scripts.eval_service_intake
$env:APP_CONFIG_FILE = '.local/m106-live.json'
.venv\Scripts\python.exe -m scripts.eval_service_intake --deepseek
```

第一条仅运行本机规则。第二条读取工作台的现有服务端配置，使用模型对比同一批样例；配置缺失时记录 `unconfigured`。运行时不会打印密钥。首次真实调用前应核对样例文件仍为虚构内容。

- 「意图一致」比较查历史、新报修、追加结果或未知。
- 「完整一致」要求意图、查找条件、事实内容三项均与人工标注一致。每项差异计为一处需要人补填或更改的字段。
- 「预计需追问」按意图和关键字段缺失估算，以每条样例最多一次合并追问计。该数字未包含查到多个档案后的人工选择，也未测量实际对话轮数。

2026-11-15 使用工作台配置完成 12 次 `deepseek-flash` 调用。

| 方式 | 意图一致 | 完整一致 | 待改填字段 | 预计需追问的样例 |
| --- | ---: | ---: | ---: | ---: |
| 本机规则 | 9/12 | 7/12 | 10 | 8 |
| DeepSeek | 12/12 | 5/12 | 9 | 5 |

模型从部分口语中正确摘出了维修经过。它也把「样例乙区」缩成「乙区」，漏掉带标签的地址，并将「处理过了，帮我补记」当作处理结果。追问估计下降包含这种误填带来的影响。首轮结果支持继续评估模型对模糊意图和草稿的帮助，售后工作台继续使用本机规则。逐项输出见[真实模型对比](deepseek-results-2026-11-15.json)及[首次本机基线](baseline-results.json)。
