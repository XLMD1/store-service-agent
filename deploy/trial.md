# 门店试用交接单

按 [PRD 第 13.4 节](../docs/prd/store-service-agent-prd-v1.0.md#134-v1-发布门槛) 核对。当前为本机审核阶段。试用时记录日期、设备与系统、账号角色、版本或提交号、实际结果和异常。截图及共享记录使用脱敏信息。

| 项目 | 已确认的试用范围与待补条件 |
| --- | --- |
| 服务和访问范围 | 门店常开电脑承载服务，师傅外出需用手机流量访问。待确认具体主机、可用的远程入口、HTTPS 地址与维护人 |
| 首批客户端 | 首批手机为安卓和鸿蒙，各记录一台真机的型号、系统版本及浏览器。先验收网页登录，安装、更新与卸载另行核定 |
| 业务责任 | 各库房期初盘点和建账时点 T0，谁持续登记库存、接单、核定和结算工费 |
| 备份责任 | 谁执行、存在哪里、保留多久、最近一次成功恢复时间及原件核对结果 |

同一台电脑同时试用两个账号时，可用 Edge 普通窗口登录老板账号，再用 InPrivate 窗口登录师傅账号。普通窗口的多个标签页共享同一登录身份。

## 外出访问试验

门店常开电脑运行应用与 PostgreSQL。试用入口通过 HTTPS 同源提供工作台和 API，应用的 origin 与手机使用的地址一致，登录 Cookie 启用 Secure。数据库仅供服务端访问。现有 127.0.0.1:8002 用于本机审核。

安卓与鸿蒙分别关闭 Wi-Fi，用移动网络打开统一地址、登录、上传样例照片并查回原件。电脑端核对同一记录；移动网络短暂中断后核对原操作回执。两种系统分别记录结果。

## 按岗位试走

1. 接单员用手机提交获准使用的售后原件，授权另一位接单员核对并归档。在电脑按电话或地址查回，打开原件核对，再撤销原件授权验证访问范围。
2. 老板安排一笔已核实的新账期工单，师傅填写实际工作、工费和实际已扣金额。老板逐项核定，按真实付款或扣款依据登记；双方分别核对本人明细、待付及已结金额。
3. 师傅用铭牌完整型号和故障码查维修辅助，打开引用页核对含义与厂家建议。对缺资料、相似型号及紧急提示分别记录专业判断；提交一条已脱敏的案例，交给具备审核权限的人员核对。
4. 在试用库用两个独立账号分别登录手机和电脑，确认一笔库存操作后另一端重新查询余额。关闭一个客户端，检查另一端仍可查询。用样例记录测试提交时断网，重连后先查原操作回执与流水，核对只产生一次业务效果。
5. 在选定平台的干净设备安装、更新、卸载并重装，检查统一服务的数据、权限、版本兼容提示。按[运行与恢复说明](README.md)将备份恢复到独立环境后读回原件、知识版本、回执和库存。

## 放行与回退

负责人核对[逐项技术验收](../docs/plans/m4-02-acceptance.md)、专业评审和上述实机结果，写明未覆盖项、影响及决定。出现重复记账、越权访问、原件缺失或机型引用错误时，暂停受影响的写入或资料发布，保存原操作号、版本及脱敏错误记录。在独立环境验证匹配的应用版本、迁移版次与备份后，再由负责人决定恢复步骤及停写期间的业务核对。
