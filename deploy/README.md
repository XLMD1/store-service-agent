# M4-01 运行与备份恢复

当前使用 FastAPI 和 PostgreSQL。8002 本机审核环境沿用现有配置及原件目录。[本机后端启动说明](../docs/guides/backend-development.md)

## 创建一致备份

1. 负责人安排停写窗口，等待运行中的任务到达可恢复状态，暂停应用写入，然后记录数据库迁移版次和备份时间。
2. 对源库执行 `pg_dump --format=custom --file=<备份目录>/database.dump --dbname=<源库名>`。同一停写窗口内完整复制配置项 `source_files_dir` 所指的售后原件目录。
3. 用 `pg_restore --list <备份目录>/database.dump` 核对目录可读，记下备份和原件的文件数、大小和 SHA-256，再恢复应用服务。说明书扫描、资料版本和审计事件随数据库归档，任务、检查点、操作及流水也在库内。
4. 在限制访问的存储位置保管备份，配置说明仅记录迁移版次、源文件目录和所需配置项。数据库密码和模型密钥独立保管。备份频率、留存和存放位置由负责人在试用前核定。

## 在独立环境恢复

1. 创建新空库和新附件目录。应用配置指向这两个新路径，试验实例绑定独立回环端口。
2. 执行 `pg_restore --no-owner --exit-on-error --single-transaction --dbname=<新空库名> <归档路径>`，将原件备份还原到新路径。核对迁移版次、附件文件数和哈希，再用匹配的应用版本启动。
3. 在恢复实例读取并比对资料原图、售后原件、未完任务、已确认操作回执和库存余额。核对任务恢复前后的原单、流水和操作记录数量，检查是否发生重复记账。记录环境、差异和复验结果。

## 首轮隔离演练

2026-11-24 在本机 PostgreSQL 18 新建两个隔离数据库，使用虚构图片和业务数据。对源库执行自定义格式备份，并复制售后照片目录。恢复到新空库及新原件目录后，通过实际应用接口逐项核对。

| 检查 | 结果 |
| --- | --- |
| 已发布说明书、核对与发布事件、原始扫描字节 | 一致 |
| 售后来源与原始照片字节 | 一致 |
| 部分完成的入库任务及操作回执 | 一项已完成、一项待确认，回执一致 |
| 库存余额、流水、原单、操作及任务检查点记录数量 | 一致，恢复和读回未新增记账 |

正式试用环境的备份策略、实际恢复耗时和例行演练责任仍待验收。
